Manages a Lightdash user attribute and the values assigned to groups. User attributes are referenced by name from dbt, for example in `required_attributes` to restrict access to dimensions and tables, and in `sql_filter` as `${lightdash.attributes.<name>}` for row-level filtering.

This resource manages the name, the description, the `attribute_defaults`, and the group values. It does not manage values assigned to individual users. The Lightdash API replaces the whole attribute on every update, so the resource reads the current user values and sends them back unchanged. Values set in the Lightdash UI are kept, with one exception: the update reads the user values and then writes them back in a separate request, so a value that a user changes in the Lightdash UI between those two requests is overwritten. Lightdash has no way to prevent this. Avoid changing user values in the Lightdash UI while `terraform apply` updates this resource. Assign user values in the Lightdash UI.

Lightdash treats a user's own values and the values of the groups they belong to as one set. A user who has no value of their own gets `attribute_defaults`. If the attribute has no default and the user has no value, a query that references the attribute fails with `Forbidden` instead of running. A default applies to every user without their own value, so a broad default gives those users access to all of the data that default matches. See the [Lightdash documentation](https://docs.lightdash.com/workspace-admin/user-attributes) for how values and defaults are resolved.

Each group in `groups` must belong to the organization, and each group can appear only once. Group UUIDs must be lowercase, which is how Lightdash returns them.
